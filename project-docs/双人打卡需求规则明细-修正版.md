# 双人打卡（双人合照）方案需求-规则明细（修正版）

> 基于初稿修正，修补逻辑漏洞。标注 `[修正]` 的内容为本次修改项。

---

## 1. 岗位人员考勤打卡流程

### 1.1 打卡流程总述

（1）**首位岗位人员**考勤打卡时默认进行单人打卡（按现考勤打卡操作方式一致）；

（2）**自第二个考勤人员开始**，对后续考勤打卡人员根据设定的概率、时间等配置指标（详细配置规则见第3点），抽取是否需要双人合拍：

- ① 被抽中需双人合拍的，考勤打卡人需从**合拍候选人池**中指定岗位人员配合其双人打卡（双人合照），考勤人员操作考勤打卡时与指定人员合拍（打卡记录中显示合拍人员信息）；
- ② 未被抽中需双人合拍的，可直接操作考勤打卡，无需合拍确认；
- ③ 考勤打卡人员被指定人拒绝后，可再次更换指定人员配合合拍；
- ④ 当天多次上下班打卡的，每一次打上下班卡时重新抽取是否需要双人合拍。

### [修正] 1.2 合拍候选人池定义

**上班卡候选人池：** 当日该项目下已成功打卡上班、且当前未被其他合拍请求锁定的岗位人员。

**下班卡候选人池：** 当日该项目下已打卡上班但尚未打卡下班、且当前未被其他合拍请求锁定的岗位人员。

> **修正说明：** 原规则"下班卡选未打卡下班的人员"与"从已考勤人员中指定"存在矛盾。现明确下班卡候选人池为"已打上班卡但未打下班卡的人员"。

### [修正] 1.3 候选人池枯竭兜底

当候选人池为空时（如项目仅剩一名人员未打下班卡、或所有候选人均已被其他合拍请求锁定），系统自动降级为单人打卡，并记录降级原因为"候选人池枯竭"。

> **修正说明：** 原规则未考虑最后一人打下班卡时无人可合拍的场景，新增此兜底逻辑。

### [修正] 1.4 合拍人锁定机制

当打卡人指定合拍人后，该合拍人进入"**合拍中**"锁定状态，在此期间不接受其他打卡人的合拍请求，避免并发冲突。

锁定在以下情况下释放：
- 合拍人接受并完成合拍；
- 合拍人拒绝（或超时）；
- 打卡人主动更换合拍人。

> **修正说明：** 原规则未考虑A和C同时指定B为合拍人的并发场景，新增锁定机制。

## 2. [修正] 合拍操作规则

### 2.1 合拍方式

合拍**必须调用手机摄像头实时拍摄**，禁止从相册选取图片，禁止使用预录视频。拍摄时系统自动记录拍摄时间戳与GPS定位信息。

### 2.2 合拍周期

合拍周期自**合拍人签收（收到通知并查看请求）时**开始计时，而非打卡人发出指定时。单位配置为"分钟"。

> **修正说明：** 原规则未明确计时起点。若从打卡人发起开始计时，通知延迟会吞掉合拍人可用时间。

### 2.3 赣建宝小程序合拍记录

赣建宝小程序-我的-新增"**考勤打卡合拍记录**"功能，三个页签：

| 页签 | 展示内容 |
|------|----------|
| **待合拍** | 需我配合合拍的请求列表。展示考勤打卡人（姓名、岗位、手机号），操作栏提供【接受】【拒绝】按钮。点击【接受】进入合拍确认页（单位名称、人员姓名、岗位类型、手机号），页面提供【确认接受】【拒绝】。确认接受后进入实时合拍拍摄。 |
| **已合拍** | 我已完成配合的合拍记录 |
| **他人协助合拍** | 我发起、他人配合的合拍记录 |

### 2.4 合拍超时及拒绝

① 合拍人收到合拍提醒后，可在合拍确认页操作【拒绝】并填写拒绝原因；

② 合拍人未在合拍周期内配合且未操作【拒绝】，系统默认拒绝，拒绝原因标记为"**超时未合拍**"；

③ 考勤打卡人在合拍周期内被拒绝或超时后，可重新指定下一个合拍人，直至：

- **候选人池仍有可选人员且未达更换次数上限时**：可继续更换。
- **[修正] 候选人池仅剩最后一人时：** 该合拍人不可拒绝，系统提示"**您已无法更换，请配合完成合拍**"。若该最后一人仍拒绝/超时，系统降级为单人打卡并记录降级原因。
- **候选人池已空时：** 系统降级为单人打卡，记录降级原因"候选人池枯竭"。

> **修正说明：** 原规则"最后一个合拍不得拒绝"但未说明拒绝后怎么办，新增降级兜底。

## 4. 双人打卡规则配置

### 4.1 全局配置

展示自江西省级组织域开始下属所有地市区县的组织域，组织域后方新增"状态""操作"两栏：

| 字段 | 说明 |
|------|------|
| **状态** | 是否启用双人打卡合拍 |
| **操作** | 【合拍规则配置】按钮，点击弹出配置窗口 |

配置内容：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 双人打卡合拍启用 | 按地市、区县配置是否启用（未单独配置项目时，组织域下所有项目按此规则） | 关闭 |
| 上班卡抽取率 | 0-100%区间 | 100% |
| 下班卡抽取率 | 0-100%区间 | **[修正] 50%**（建议值，待确认） |
| 更换次数 | 打卡人可更换合拍人选的最大次数 | 待定 |
| 合拍周期 | 合拍人签收后完成合拍的时限 | 待定（单位：分钟） |
| 是否要求同一公司 | 合拍人是否必须与打卡人同属一家参建单位 | 否 |
| 是否可指定已下班人员 | 合拍候选人是否包含已打下班卡的人员 | 否 |

> **[修正] 原规则下班卡默认值0%导致该逻辑永不触发，建议给合理默认值，最终取值待与甲方确认。**

**组织域配置下发规则：** 配置窗口中新增下一级组织域多选项，选择后默认下级组织域按此合拍规则生效。例如在江西省级组织域配置合拍规则，需选择下一级地市级组织域，保存时提示"保存后将更新您选择的组织域（包括下级组织域）全部合拍配置规则"。地市级配置同理。

### 4.2 高级配置（项目级）

右上角新增【双人打卡合拍配置】按钮，可单独为项目配置规则。**项目级配置优先级高于全局配置。**

| 字段 | 说明 |
|------|------|
| 监管项目名称 | 项目名称 |
| 施工许可编号 | 施工许可证号 |
| 项目类型 | 房屋建筑/市政基础设施等 |
| 项目状态 | 在建/停工/竣工等 |
| 管理区域 | 所属区县 |
| 建设单位 | 建设单位名称 |
| 施工单位 | 施工单位名称 |
| 监理单位 | 监理单位名称 |
| 是否启用 | 是/否 |
| 抽取率 | 上班卡/下班卡分别配置 |
| 更换次数 | 自定义 |
| 合拍周期 | 自定义（分钟） |

筛选项：监管项目名称、项目类型、项目状态、管理区域、单位名称。

## 5. 双人打卡考勤预警

以**人员**为维度统计，每月初固定存储上月数据，当月数据按天更新。

| 预警类型 | 判定规则 |
|----------|----------|
| **高频拒绝** | 7日内拒绝次数 ≥ 3次 |
| **首人到岗** | **[修正]** 项目下有其他岗位人员的情况下，连续7天首位打卡。**但以下情况除外：** ① 该人员岗位为门卫/保安等固定首人到岗岗位（岗位白名单可配置）；② 项目仅此一人在册 |
| **打卡人位置异常** | 打卡人位置与合拍人位置相差 ≥ 2公里 |
| **位置高度重合** | **[修正]** 连续30天内，打卡人与合拍人GPS位置高度重合（误差≤50米）累计≥10次 |
| **高频超时未响应** | 7日内超时未响应 ≥ 3次 |
| **合拍时间过短** | **[修正]** 从合拍拍摄界面打开到快门触发 < 3秒（原5秒阈值偏高，提前站好位3秒足够完成拍摄），判定疑似预录图片/快速摆拍 |

> **修正说明：** "位置高度重合"原规则未说明统计周期，现明确为连续30天。"首人到岗"增加岗位白名单排除逻辑。

页面展示：人员姓名、身份证号、手机号、所在项目、岗位类型、工作状态、当月出勤天数、高频拒绝次数、首人到岗次数、位置异常次数、高频超时次数、合拍时间过短。

筛选项：年/月、人员姓名/身份证号、项目名称、岗位类型。

排序字段：高频拒绝次数、首人到岗次数、位置异常次数、高频超时次数。

## 6. 打卡协同管理

以**项目**为维度统计，每月初固定存储上月数据，当月按天更新。

| 指标 | 计算方式 |
|------|----------|
| 上班卡触发率 | 当月上班卡双人打卡合拍人次 / 当月上班卡总打卡人次 |
| 下班卡触发率 | 当月下班卡双人打卡合拍人次 / 当月下班卡总打卡人次 |
| 预警次数 | 当月该项目"双人打卡考勤预警"中预警的人数 |

展示字段：监管项目名称、施工许可编号、项目类型、项目状态、管理区域、双人打卡触发率、预警次数。

筛选项：年/月、监管项目名称、项目类型、项目状态、管理区域、单位名称。

排序字段：触发率、预警次数。

## 7. 人员考勤设备

① 赣建宝小程序打卡时自动记录当前登录微信号及手机型号，形成账号-微信号-手机对应关系，实时同步至监管端"人员考勤设备"菜单；

② 双人打卡规则配置中新增"**考勤打卡设备及微信号更换频次阈值**"配置，默认当月最多更换2次。超出阈值后人员无法打卡，提示"您当月更换考勤打卡设备或微信号已超次数，请绑定原考勤打卡设备操作打卡或联系属地主管部门处理"，该人员最后一台打卡设备状态转为"已限制"；

③ **[修正]** 新增"**设备异常申报**"通道：人员可在小程序内提交设备损坏/丢失申报（需上传佐证材料），属地监管审核通过后可解除限制，不占用当月更换次数；

> **修正说明：** 原规则更换2次限制过刚性，手机损坏/丢失场景无法处理，增加申报通道。

④ 人员变更绑定微信或设备后，打卡时系统自动记录所有打卡设备信息和最新一次打卡时间。

展示字段：人员姓名、身份证号、所在项目、岗位类型、工作状态、当月出勤天数、账号、绑定手机号、绑定微信号。

筛选项：人员姓名/身份证号、项目名称、岗位类型。

## 8. 跨天与重置规则

双人打卡配置要求当天未完成打卡的，双人考勤配置要求保留；**跨天重置**，次日按新的抽取规则重新抽取。

双人打卡（双人合照）方案需求 — 规则明细（修正版）

版本：v1.3 日期：2026-07-31 基于同事初稿修正 + 需求评审会议（2026-08-04）同步

1. 岗位人员考勤打卡流程

1.1 打卡流程总述

（1）首位岗位人员考勤打卡时默认进行单人打卡（按现考勤打卡操作方式一致）；

（2）自第二个考勤人员开始，对后续考勤打卡人员根据设定的概率、时间等配置指标抽取是否需要双人合拍：

  • ① 被抽中需双人合拍的，考勤打卡人需从合拍候选人池中指定岗位人员配合其双人打卡（双人合照），考勤人员操作考勤打卡时与指定人员合拍（打卡记录中显示合拍人员信息）；
  • ② 未被抽中需双人合拍的，可直接操作考勤打卡，无需合拍确认；
  • ③ 考勤打卡人员被指定人拒绝后，可再次更换指定人员配合合拍；
  • ④ 当天多次上下班打卡的，每一次打上下班卡时重新抽取是否需要双人合拍。

修正1.2 合拍候选人池定义

上班卡候选人池：当日该项目下已成功打卡上班、且当前未被其他合拍请求锁定的岗位人员。

下班卡候选人池：当日该项目下已打卡上班但尚未打卡下班、且当前未被其他合拍请求锁定的岗位人员。

修正说明：原规则"下班卡选未打卡下班的人员"与"从已考勤人员中指定"存在矛盾。现明确下班卡候选人池为"已打上班卡但未打下班卡的人员"。

修正1.3 候选人池枯竭兜底

当候选人池为空时（如项目仅剩一名人员未打下班卡、或所有候选人均已被其他合拍请求锁定），系统自动降级为单人打卡，并记录降级原因为"候选人池枯竭"。

修正说明：原规则未考虑最后一人打下班卡时无人可合拍的场景，新增此兜底逻辑。

修正1.4 合拍人锁定机制

当打卡人指定合拍人后，该合拍人进入"合拍中"锁定状态，在此期间不接受其他打卡人的合拍请求，避免并发冲突。

锁定在以下情况下释放：合拍人接受并完成合拍；合拍人拒绝（或超时）；打卡人主动更换合拍人。

修正说明：原规则未考虑A和C同时指定B为合拍人的并发场景，新增锁定机制。

新增1.5 微信刷脸验证（被抽中前置环节）

当岗位人员被抽中需双人合拍时，点击打卡按钮后先进行微信真人刷脸验证，通过后方可进入双人打卡验证页面。

  • 刷脸验证通过 → 进入双人打卡流程（自选/系统随机分配合拍人）
  • 刷脸验证失败 → 返回打卡页，不能完成打卡
  • 当日免重复：当日双人打卡流程未走完前，退出小程序再进入时点击打卡按钮无需重复刷脸，直接进入双人打卡验证页
  • 刷脸验证采用微信原生人脸核验接口，确保操作者为账号本人

新增1.6 合拍人产生方式（自选/系统随机）

合拍人的产生方式为运维配置项，支持两种模式：

模式说明流程
系统随机（默认）系统从候选人池中随机抽取一名合拍人被抽中 → 刷脸 → 直接进入合拍触发页
自选被抽中人员自行从可选人员列表中选择合拍人被抽中 → 刷脸 → 进入合拍人选择页 → 选择合拍人 → 进入合拍触发页

自选模式规则：

  • 可选人员列表来源：当前工地在场的岗位人员，已打上班卡但未打下班卡的人员，排除自己
  • 选择限时：运维配置项，默认5分钟。超时未选择则系统按随机抽取原则抽取一名
  • 可选列表为空时，降级为单人打卡
  • 确认机制保留：被选中的合拍人仍需在确认窗口内接受/拒绝

2. 合拍操作规则 修正

2.1 合拍方式

合拍必须调用手机摄像头实时拍摄，禁止从相册选取图片，禁止使用预录视频。拍摄时系统自动记录拍摄时间戳与GPS定位信息。

2.2 合拍周期

合拍周期自合拍人签收（收到通知并查看请求）时开始计时，而非打卡人发出指定时。单位配置为"分钟"。

修正说明：原规则未明确计时起点。若从打卡人发起开始计时，通知延迟会吞掉合拍人可用时间。

2.3 赣建宝小程序合拍验证

赣建宝小程序-我的-新增"合拍验证"功能，三个页签：

页签展示内容
验证请求收到的待处理合拍打卡请求。展示打卡人信息（姓名、岗位、手机号），操作栏提供【去处理】按钮，跳转至邀请处理页完成接受/拒绝。
抽验记录我作为打卡人的全部合拍核验记录
协助记录我作为合拍人协助他人的合拍记录

2.4 合拍超时及拒绝

① 合拍人收到合拍提醒后，可在合拍确认页操作【拒绝】并填写拒绝原因；② 合拍人未在确认窗口内配合且未操作【拒绝】，系统默认拒绝，拒绝原因标记为"超时未合拍"；③ 合拍人被拒绝或超时后，系统判定是否超过配置的更换次数上限：未超过则系统自动更换下一个候选人（回到抽取合拍人步骤）；超过则降级为单人打卡。

修正说明：原规则"最后一个合拍不得拒绝"但未说明拒绝后怎么办。现明确流程：合拍人拒绝/超时→系统判定"是否大于配置更换次数N"（默认N=2）→未超过则自动更换候选人重新抽取→超过则降级为单人打卡。候选人池枯竭直接降级，不经过N次判定。

新增2.5 拍照设备随机分配

合拍人确认合拍后，系统随机判定由谁的手机进行双人合拍拍照。拍照设备分配概率为运维配置项。

配置选项说明
默认各50%打卡人手机50% / 合拍人手机50%
仅打卡人手机100%由打卡人手机拍照（原流程）
70%打卡人 / 30%合拍人偏向打卡人手机
30%打卡人 / 70%合拍人偏向合拍人手机

合拍人手机拍照时的处理：

  • 打卡人端：在合拍触发页点击"开始拍照"时弹窗提示"系统抽中需使用合拍人 XX 手机进行合拍验证，请配合合拍人完整验证"，关闭弹窗后拍照按钮禁用，显示"等待合拍人拍照中"
  • 合拍人端：在合拍确认结果页调整提示内容，新增"📷 开始合拍"按钮，点击后跳转合拍拍照页
  • 系统在合拍人确认后立即判定拍照设备，并分别向双方推送对应提示

新增2.6 合拍待办红点提醒

赣建宝小程序"我的"页面中"合拍验证"应用图标上，当存在待处理合拍代办时，显示红点标识。红点在合拍人有待处理的合拍请求时显示，无待处理时隐藏。

3. 被指定提醒

赣建宝小程序内消息提醒（小程序订阅消息 / 站内信）。

4. 双人打卡规则配置

4.1 全局配置

展示自江西省级组织域开始下属所有地市区县的组织域，组织域后方新增"状态""操作"两栏：

字段说明
状态是否启用双人打卡合拍
操作【合拍规则配置】按钮，点击弹出配置窗口

配置内容：

配置项说明默认值
双人打卡合拍启用按地市、区县配置是否启用关闭
上班卡抽取率0-100%区间30%
下班卡抽取率0-100%区间修正15%（建议值）
更换次数打卡人可更换合拍人选的最大次数。系统自动在上一个合拍人拒绝/超时后抽取下一个候选人。2次（共3人）
合拍周期含确认窗口和执行窗口两个计时器。确认窗口：合拍人签收后完成接受/拒绝的时限，默认5分钟。执行窗口：自打卡人被抽中时起算，完成合拍的时限，默认15分钟。
上述两个时长均为运维可配置参数，各组织域可按需调整。		确认5分钟 / 执行15分钟
是否要求同一公司合拍人是否必须与打卡人同属一家参建单位否

新增合拍人产生方式系统随机 / 自选。自选模式下被抽中人员从可选列表中自行选择合拍人系统随机

新增拍照设备分配双人合拍拍照由谁手机完成的概率分配默认各50%

组织域配置下发规则：配置窗口中新增下一级组织域多选项，选择后默认下级组织域按此合拍规则生效。

新增4.2 高级配置（项目级）

可单独为项目配置规则，项目级配置优先级高于全局配置。筛选项：监管项目名称、项目类型、项目状态、管理区域、单位名称。

权限下放：项目规则例外的添加/解除权限下放至地市、区县级单位。各下级单位可自行管理其辖区内的特殊规则项目，无需逐级上报省级审批。具体权限规则：

  • 省级：可管理全省所有项目的规则例外
  • 市级：可管理本市及下辖区县内的项目规则例外
  • 区县级：可管理本区县内的项目规则例外
  • 下级单位添加的例外项目，上级单位可查看但不可修改；上级单位可强制解除下级的例外设置

5. 数据统计 调整

取消风险预警，改为展示真实数据统计。不进行风险评级，不以颜色标注风险等级。监管人员可查看客观数据自行判断。

以人员和项目两个维度展示统计数据，每月初固定存储上月数据，当月数据按天更新。

5.1 顶部统计卡片

统计项说明
累计抽验上线至今双人打卡抽验总人次
拒绝次数合拍人拒绝合拍请求的累计次数
通过次数双人合拍核验通过的累计次数
未通过次数双人合拍核验未通过的累计次数
降级次数因候选人池枯竭或超时降级为单人打卡的累计次数

5.2 人员统计表

字段：姓名 / 项目 / 抽中次数 / 拒绝次数 / 通过次数 / 未通过次数 / 降级次数

5.3 项目统计表

字段：项目名称 / 项目区划 / 抽验总人次 / 拒绝次数 / 通过次数 / 未通过次数 / 降级次数

调整说明：原风险预警模块（高频拒绝、首人到岗、位置异常等6类预警指标及评分体系）已移除。改为纯客观数据统计展示，监管人员根据数据自行判断，不做风险评级和颜色标注。

6. 打卡协同管理

以项目为维度统计，每月初固定存储上月数据，当月按天更新。

指标计算方式
上班卡触发率当月上班卡双人打卡合拍人次 / 当月上班卡总打卡人次
下班卡触发率当月下班卡双人打卡合拍人次 / 当月下班卡总打卡人次
异常次数当月该项目拒绝+超时+降级+未通过的合计次数

新增6.1 抽验记录详情照片展示规则

抽验记录详情页中不向监管人员展示双人打卡照片。后台可记录留存合拍照片，但前端展示页面不对外显示。详情页以"验证结果"卡片替代照片展示，注明"合拍照片已后台留存"。

7. 人员考勤设备 修正

赣建宝小程序打卡时自动记录当前登录微信号及手机型号，形成账号-微信号-手机对应关系。更换频次阈值默认当月最多更换2次，超出后无法打卡。新增设备异常申报通道供设备损坏/丢失场景。

修正说明：原规则更换2次限制过刚性，手机损坏/丢失场景无法处理，增加申报通道。

8. 跨天与重置规则

双人打卡配置要求当天未完成打卡的，双人考勤配置要求保留；跨天重置，次日按新的抽取规则重新抽取。
